面向局域网聚会的
简单文件共享

LANBucket 让您在同一网络中的设备之间轻松共享文件。 非常适合局域网聚会、大文件以及家里的快速传输。无需联网。

分布式传输。100% 无 Electron。

LANBucket 功能对比（纯文本摘要）

这是上方对比表格的纯文本版本，将 LANBucket 与 DC++、D-LAN、LocalSend、SMB 共享、云存储、Steam 本地共享和 USB 闪存盘进行对比。每一项均列出该工具是否提供此功能（是、部分支持或否）及其原因。

无需设置或配置。 LANBucket：是。DC++：否 — DC++ 要求您先添加要连接的中枢并设置共享列表，然后才能使用。D-LAN：部分支持 — D-LAN 会自动发现对等端，但您仍需选择要共享的文件夹以及下载位置。LocalSend：是。SMB 共享：否 — SMB 共享需要启用共享、设置权限并映射驱动器，通常还需要管理员权限。云存储：否 — 您必须创建账户、安装客户端并等待其同步，然后才能共享任何内容。Steam 本地共享：部分支持 — 您需要安装并登录 Steam，并启用相关的共享设置。USB 闪存盘：否 — 闪存盘必须为您的设备格式化，并逐一物理插入每台设备。

无需账户或登录。 LANBucket：是。DC++：是。D-LAN：是。LocalSend：是。SMB 共享：否 — SMB 需要有效的用户凭据或网络账户才能验证访问。云存储：否 — 云存储需要先创建并登录账户，然后才能传输文件。Steam 本地共享：否 — 您必须拥有 Steam 账户并登录才能使用任何 Steam 功能。USB 闪存盘：是。

分布式（多对多）传输。 LANBucket：是。DC++：部分支持 — DC++ 可以同时从多个对等端拉取文件，但只有在对方完成下载之后才行；LANBucket 允许从尚未拥有完整文件的对等端下载。D-LAN：是。LocalSend：否 — LocalSend 一次只在一台设备与另一台设备之间直接发送。SMB 共享：否 — SMB 共享由单一主机提供，因此所有人都从那一台机器下载。云存储：否 — 传输通过服务提供商的服务器进行，而不是在多个本地对等端之间直接进行。Steam 本地共享：否 — 内容来自单一主机，而非多个对等端共同分担负载。USB 闪存盘：否 — 闪存盘一次只能手动复制到一台机器。

自动对等发现。 LANBucket：是。DC++：否 — 没有自动发现；您必须知道并输入中枢地址才能找到其他人。D-LAN：是。LocalSend：是。SMB 共享：否 — 您需要共享的主机名或 IP 地址才能连接。云存储：否 — 没有本地对等端可供发现，一切都通过服务提供商的服务器进行。Steam 本地共享：是。USB 闪存盘：否 — 闪存盘没有网络功能，因此没有任何可供发现的内容。

同类最佳性能。 LANBucket：是。DC++：否 — DC++ 只从已拥有完整文件的对等端下载，因此当所有人同时下载一个新文件时，数据全部来自最初的共享者。D-LAN：部分支持 — D-LAN 比传统文件共享快得多，但我们在测试中测得 LANBucket 最多比 D-LAN 快约 2 倍。LocalSend：否 — 每一份副本都直接来自发送端设备，因此当多人需要该文件时，发送端的网络链路就是瓶颈。SMB 共享：否 — 所有人都从托管共享的那一台电脑下载，因此它的网络链路就是瓶颈。云存储：否 — 每次下载都要经过您的互联网连接，而它通常比局域网慢得多。Steam 本地共享：否 — 内容来自单一主机，因此该主机的网络链路就是瓶颈。USB 闪存盘：否 — 闪存盘必须逐台复制，因此每多一个人就更慢一些。

保留在您的局域网内。 LANBucket：是。DC++：部分支持 — DC++ 可以在局域网中运行，但许多公共中枢会将您的流量通过互联网转发。D-LAN：是。LocalSend：是。SMB 共享：是。云存储：否 — 云存储会将您的文件上传到互联网上的远程服务器。Steam 本地共享：部分支持 — 本地串流保留在您的局域网内，但 Steam 仍需联系其服务器为您登录。USB 闪存盘：是。

拖放共享任意文件。 LANBucket：是。DC++：否 — DC++ 共享的是您预先配置的整个文件夹，而非临时拖入的文件。D-LAN：部分支持 — D-LAN 自 1.4 版起支持拖放，但您必须先进入其共享列表才能拖入文件。LocalSend：是。SMB 共享：部分支持 — 您可以将文件拖入共享文件夹，但前提是共享和权限已设置好。云存储：是。Steam 本地共享：否 — Steam 只共享游戏和库内容，而非任意文件。USB 闪存盘：部分支持 — 您可以把文件拖到驱动器上，但它必须插入并被带到每台设备。

面向非技术用户的简洁界面。 LANBucket：是。DC++：否 — DC++ 的界面密集且技术性强，围绕中枢、槽位和下载队列构建。D-LAN：否 — D-LAN 的界面假定用户对网络和共享文件夹有一定了解。LocalSend：是。SMB 共享：否 — SMB 设置涉及操作系统设置、权限和驱动器映射，容易让非技术用户困惑。云存储：是。Steam 本地共享：是。USB 闪存盘：是。

无需互联网即可使用。 LANBucket：是。DC++：是。D-LAN：是。LocalSend：是。SMB 共享：是。云存储：否 — 云存储需要互联网连接才能访问服务提供商的服务器。Steam 本地共享：否 — Steam 通常需要联网登录后其功能才能使用。USB 闪存盘：是。

实时压缩。 LANBucket：是 — LANBucket 会在文件发送时自动压缩、在文件到达时自动解压，全程实时进行，这可以让可压缩文件的传输明显更快。DC++：否 — DC++ 传输文件时不进行任何自动压缩。D-LAN：否 — D-LAN 按原样发送文件，不进行实时压缩。LocalSend：否 — LocalSend 传输文件时不进行实时压缩。SMB 共享：否 — SMB 默认逐字节复制文件，不进行透明压缩。云存储：否 — 云上传在传输前不会实时压缩您的文件。Steam 本地共享：否 — Steam 不为文件传输提供实时压缩。USB 闪存盘：否 — 复制到闪存盘不会压缩您的文件。

LANBucket 能通过互联网使用吗？

不能，LANBucket 仅在局域网中工作。所有设备必须连接到同一 WiFi 网络或以太网局域网。这是有意为之，目的是保持您的文件私密和安全。

它能在我的公司网络上使用吗？

许多公司网络出于安全原因会阻止客户端之间的通信，这可能导致 LANBucket 无法正常工作。 LANBucket 主要为家庭和私人网络设计。

如果多播被阻止，LANBucket 还能工作吗？

很可能可以。LANBucket 有一个使用中央服务器的后备对等发现机制，因此即使您的网络阻止了多播，设备之间仍可以相互发现并共享文件。 如果该机制无效，您可以通过手动输入要连接设备的 IP 地址来连接对等端。

我所有的客户端都在同一 WiFi 网络上，但有些无法相互看到。为什么？

许多 WiFi 路由器具有“AP 隔离”或“客户端隔离”功能，会阻止连接到同一 WiFi 网络的设备相互通信。 请检查您的路由器设置，看是否启用了此功能。 此外，我们还发现，有些无线路由器/接入点在客户端处于不同频段时不允许客户端之间的流量，即一个客户端 连接到 2.4GHz，另一个连接到 5GHz。如有可能，请尝试将所有客户端连接到 WiFi 网络的同一频段，或通过以太网连接以获得最佳效果。

我可以在使用 VPN 的情况下使用它吗？

VPN 连接可能会干扰局域网发现。您可能需要断开 VPN 才能使用 LANBucket。

如果我修改了正在共享的文件会怎样？

移动、删除或修改您正在共享的文件会导致其他人无法下载。 请在其他人完成下载之前保持共享文件不动。

我的防火墙会阻止 LANBucket 吗？

Windows Defender 防火墙可能会阻止 LANBucket 发现设备。请确保将网络配置文件设置为“专用”，并在首次启动出现提示时允许 LANBucket 通过防火墙。

有 Linux 或 MacOS 支持吗？

暂时没有，但我们正在考虑。目前 LANBucket 使用 Windows 专用的 UI 框架构建，因此支持 Linux/MacOS 需要大量重写。遗憾的是，LANBucket 也不兼容 Wine/Proton，因为我们使用了那里同样未实现的 Windows API。

什么是实时压缩？

LANBucket 会在文件发送时自动压缩、在文件到达时自动解压，全部实时完成。 您无需先打包成 zip。对于压缩效果好的文件（例如某些电子游戏）， 您可能会观察到显著更快的传输速度。如果文件压缩效果不佳，压缩会自动关闭。
